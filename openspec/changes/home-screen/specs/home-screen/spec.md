## Purpose

Главный экран, который открывается при запуске: показывает последние заметки и холсты, создаёт новые одним нажатием и даёт доступ к служебным разделам из шапки.

## ADDED Requirements

### Requirement: Две половины — заметки и холсты
Главный экран SHALL делиться на две половины: слева заметки (документы-тетради), справа холсты (документы-доски). В каждой половине MUST показываться превьюшки документов (карточки), отсортированные по времени изменения, самые свежие первыми. Если превьюшек нет, половина показывает только плитку «создать».

#### Scenario: Альбомная ориентация
- **WHEN** пользователь запускает приложение в альбомной ориентации при наличии тетрадей и досок
- **THEN** слева видны превьюшки последних тетрадей, справа — последних досок, обе половины занимают по половине ширины экрана

#### Scenario: Портретная ориентация
- **WHEN** пользователь держит планшет вертикально
- **THEN** экран остаётся поделённым на две половины, а число показанных превьюшек уменьшается под доступное место

#### Scenario: Пока нет ни одного документа
- **WHEN** в хранилище нет ни тетрадей, ни досок
- **THEN** в каждой половине виден только пустой заголовок и плитка «создать»

### Requirement: Только последние документы
В каждой половине SHALL показываться только ограниченное число последних документов, а не все. Число MUST определяться доступным местом (ориентация и размер экрана) и не превышать заданного предела. Остальные документы доступны через полный список.

#### Scenario: Документов больше, чем помещается
- **WHEN** в хранилище 30 тетрадей, а в половине помещается 5 превьюшек
- **THEN** показываются пять самых недавно изменённых тетрадей, остальные видны в полном списке

### Requirement: Полный список по тапу на заголовок
Тап по заголовку половины («Заметки» или «Холсты») SHALL открывать полный список документов этого вида, где виден весь набор с теми же карточками; из полного списка документ открывается, переименовывается и удаляется так же, как раньше. Возврат из списка ведёт на главный экран.

#### Scenario: Открытие полного списка
- **WHEN** пользователь нажимает заголовок «Холсты»
- **THEN** открывается экран со всеми досками, отсортированными от новых к старым

#### Scenario: Открытие документа из списка
- **WHEN** пользователь в полном списке нажимает превьюшку тетради
- **THEN** открывается редактор этой тетради

### Requirement: Тап по превьюшке открывает документ
Нажатие на превьюшку документа на главном экране SHALL открывать этот документ в редакторе.

#### Scenario: Продолжить недавнюю заметку
- **WHEN** пользователь нажимает превьюшку последней тетради
- **THEN** открывается редактор этой тетради на сохранённом месте

### Requirement: Плитка «создать»
Левая верхняя превьюшка в каждой половине SHALL быть плиткой «создать»: пустой, с плюсом. Нажатие MUST сразу создавать документ и открывать его в редакторе без диалога и без захода в меню. Левая плитка создаёт тетрадь с именем — датой `дд.мм.гггг` и шаблоном страниц «линейка»; правая — доску с именем — датой. При совпадении имени с существующим документом MUST действовать существующий механизм уникальных имён (суффикс « (2)», « (3)»…), без перезаписи.

#### Scenario: Новая заметка одним нажатием
- **WHEN** пользователь нажимает плитку «создать» в левой половине
- **THEN** сразу открывается редактор новой тетради «дд.мм.гггг» с одной страницей в линейку, диалог не показывается

#### Scenario: Новый холст одним нажатием
- **WHEN** пользователь нажимает плитку «создать» в правой половине
- **THEN** сразу открывается новая доска с именем — сегодняшней датой

#### Scenario: Имя уже занято
- **WHEN** пользователь второй раз за день нажимает плитку «создать» в левой половине
- **THEN** создаётся отдельная тетрадь с суффиксом « (2)», первая не изменяется

### Requirement: Шапка вместо меню
Служебные разделы «О программе», «Диагностика пера», «Холст» и «Поиск по рукописи» SHALL быть доступны плоским текстом (без карточек и значков-кнопок) в шапке главного экрана; список из пяти пунктов MUST исчезнуть. Тап по каждому тексту открывает соответствующий экран, возврат ведёт на главный экран.

#### Scenario: Переход в диагностику
- **WHEN** пользователь нажимает «Диагностика пера» в шапке
- **THEN** открывается экран диагностики пера

#### Scenario: Поиск
- **WHEN** пользователь нажимает «Поиск по рукописи» в шапке
- **THEN** открывается экран поиска по рукописи

### Requirement: Открыть PDF с главного экрана
В заголовке левой половины SHALL быть небольшая ссылка «Открыть PDF»; нажатие запускает выбор PDF и создаёт из него тетрадь так же, как раньше из раздела «Заметки».

#### Scenario: Импорт PDF
- **WHEN** пользователь нажимает «Открыть PDF» и выбирает файл
- **THEN** создаётся тетрадь из страниц PDF и открывается редактор

### Requirement: Доступ к файлам на главном экране
Если у приложения нет доступа ко всем файлам, главный экран SHALL показывать объяснение и кнопку «Разрешить доступ» вместо половин; после выдачи доступа и возврата в приложение MUST сразу показываться обычный вид без перезапуска. Ссылки шапки при этом остаются доступными.

#### Scenario: Первый запуск без доступа
- **WHEN** пользователь запускает приложение, не выдав доступ к файлам
- **THEN** вместо половин видны объяснение и кнопка «Разрешить доступ», в шапке работают служебные ссылки

#### Scenario: Возврат из настроек
- **WHEN** пользователь выдал доступ и вернулся в приложение
- **THEN** главный экран показывает половины с документами без перезапуска
