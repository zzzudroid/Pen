## Context

Документы — файлы `.pen` в `Documents/Pen/`. Идентификатор документа сейчас равен имени файла (`NotebookStore.file(id)`, маршрут `note/{id}?page=N`), формат v2 хранит страницы, `kind`, `boardView`, `source.pdf` (`NotebookFormat`). Лассо уже умеет выделять штрихи и переносить их одной командой истории (`History`, `Replace`). Индекс поиска по рукописи (`recognition/SearchIndex`) пересканирует только изменённые тетради по `meta.modified`. Мотивация — в `proposal.md`, требования — в `specs/*/spec.md`.

## Goals / Non-Goals

**Goals:** ссылки переживают переименование; переход и возврат без потери места; ничего не ломается, если цель исчезла.

**Non-Goals:** плитка-ссылка с превью, автоссылки по распознанному тексту, вырезка схемы в заметку, кликабельные ссылки в PDF.

## Decisions

1. **Идентификатор — UUID в `meta.json` (`docId`).** Имя файла остаётся только названием для человека. Документу без идентификатора (v1/v2) он выдаётся в памяти при открытии и записывается при первом сохранении — открытие без правок файл не меняет. Альтернатива — вывести идентификатор из имени файла: ломается при переименовании, ради чего всё и затевается.
2. **Формат v3 — расширение `meta.json`.** Поля: `docId`, `links[]` (`{id, pageId, rect[left,top,right,bottom], target{docId, bookmarkId?, view?{scale,tx,ty}}}`), `bookmarks[]` (`{id, name, view{scale,tx,ty}}`; только у доски). Штрихи и `pages/*.strokes` не меняются. `FORMAT_VERSION = 3`; файлы v1/v2 читаются, пустые списки; файл с большей версией — понятная ошибка (как сейчас). Запись всегда v3.
3. **Индекс «идентификатор → файл».** JSON во внутренней памяти (`filesDir`), строится по образцу `SearchIndex`: ключ свежести — `meta.modified`, перечитываются только изменённые файлы (читается лишь `meta.json` из zip, без штрихов). Запись `{docId → имя файла, название, вид, modified, ссылки[]}` — тот же проход собирает и данные для обратных ссылок (п. 12), поэтому отдельного сканирования не нужно. Альтернатива — искать по всем файлам при каждом переходе: медленно при десятках тетрадей.
4. **Цель недоступна.** При открытии ссылки документ ищется в индексе; если записи нет или файл не читается — сообщение «Документ недоступен», переход не выполняется; ссылка остаётся и показывается приглушённой, её можно удалить. Закладка не найдена — открывается доска в последнем виде и сообщение.
5. **Закладки — только у доски**, в `meta.json`: имя и вид (масштаб и сдвиг в тех же единицах, что `boardView`). Постановка использует текущий `viewport`. Пользовательские операции (поставить, переименовать, удалить) идут через команды истории не обязательно: закладки — служебные данные доски, а не содержимое страницы; отмены не требуют (решение: проще и без неожиданных откатов закладки при отмене штрихов).
5а. **Ссылки — в истории страницы.** Создание, изменение цели и удаление ссылки — команды истории (`LinkAdded`, `LinkRemoved`, `LinkChanged`), чтобы «Отменить» работало как для штрихов (требование спецификации). Ссылки лежат в `PageState` рядом со штрихами.
6. **Перемещение выделения с ссылками.** Ссылка, область которой целиком внутри рамки выделения лассо, переносится и масштабируется вместе со штрихами (одна команда истории `Replace` расширяется переносом ссылок); задетые частично остаются на месте. Обоснование: ссылку почти всегда создают на надпись и ждут, что она «приклеена» к надписи; частично захваченную область переносить нельзя — получится ссылка, не совпадающая ни со старым, ни с новым положением надписи.
7. **Тап по ссылке — только пальцем.** В `DrawingSurface` палец уже никогда не рисует (сдвиг, масштаб, тап-жесты, режим «стирать пальцем»). Короткий тап одним пальцем (по критерию существующего распознавания тапа) по области ссылки открывает цель; пером можно писать поверх области без перехода. Режим «стирать пальцем» включён — тап ссылку не открывает (палец занят стиранием). Область ссылки подсвечивается в отдельном слое (фон + подчёркивание), в штрихи и в PDF не попадает.
8. **Возврат — стек в навигации.** Переход открывает цель обычным `navigate` (маршрут `note/{id}?page=N` дополняется параметрами вида/закладки), поэтому системная «Назад» возвращает на предыдущий экран. Положение источника (страница, сдвиг, масштаб) сохраняется в `SavedStateHandle` экрана-источника и восстанавливается при возврате. Идентификатор в маршруте — теперь `docId`, а не имя файла; старые маршруты по имени продолжают работать через индекс.
9. **Выбор цели ссылки.** Диалог со списком документов из индекса (тетради и доски) и, для доски, списком закладок + пункт «текущий вид» (вид выбранной доски не знаем из чужого экрана — «текущий вид» доступен, когда ссылка создаётся внутри этой же доски; для чужой доски — закладка или «в последнем виде»). Это снимает необходимость открывать доску, чтобы выбрать место.
10. **Обратные ссылки — из индекса п. 3.** Для каждого документа индекс хранит список его исходящих ссылок (`{pageId, rect, targetDocId, bookmarkId?}`); обратные для документа D — выборка по `targetDocId == D`. Панель «Откуда ссылаются» показывает название источника, номер страницы (по позиции `pageId` в порядке страниц источника) и ведёт к месту ссылки (страница + сдвиг к области). Альтернатива — хранить обратные ссылки в самой цели: рассинхронизация при правках источника и запись в чужой файл, поэтому не берём.
11. **PDF-экспорт.** `PdfExporter` не меняется: подсветка ссылок и сами ссылки в PDF не выводятся.

## Risks / Trade-offs

- [Индекс по `meta.modified` не заметит правку файла вне приложения (синхронизация с ПК)] → при открытии списка и перед переходом по ссылке проверяется время изменения нужного файла; полная пересборка по кнопке/при сбое чтения.
- [Две копии файла с одним `docId` (скопировали вручную)] → индекс берёт самый свежий по `modified`, дубликат помечается; при создании ссылки используется первый — известное ограничение.
- [Область ссылки в мировых координатах — страница сдвигается/масштабируется лассо] → правило п. 6; ссылка вне выделения остаётся на месте.
- [Размер `meta.json` растёт с числом ссылок и закладок] → ссылки компактны; лимиты не вводим.

## Migration Plan

Файлы v1/v2 открываются как раньше; v3 записывается при первом сохранении. Откат: приложение прежней версии отвергает v3 с понятной ошибкой (файл не портится), поэтому перед выпуском фиксируется копия `Documents/Pen/`.
