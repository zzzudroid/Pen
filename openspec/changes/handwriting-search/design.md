## Context

Тетради лежат в `Documents/Pen/*.pen` и читаются через `NotebookStore` и `NotebookFormat`. Мотивация — в `proposal.md`, требования — в `specs/handwriting-search/spec.md`.

## Goals / Non-Goals

**Goals:** поиск по всем тетрадям офлайн, без изменения формата файлов.

**Non-Goals:** преобразование рукописи в текст в редакторе, распознавание фигур, переход на страницу результата (позже), поиск по тексту подложки PDF.

## Decisions

1. **ML Kit Digital Ink, модель `ru`.** Распознаёт на устройстве, поддерживает русский, бесплатна. Альтернативы (Tesseract по растру, облачные API) хуже работают с рукописью или требуют сети на каждый запрос.
2. **Сегментация на строки до распознавания.** ML Kit рассчитан на строку текста; целая страница даёт плохой результат. Строки выделяются по пересечению вертикальных интервалов штрихов с допуском, затем штрихи сортируются по X. Чистый Kotlin с JVM-тестами.
3. **Индекс — отдельный JSON во внутренней памяти**, а не поле в `.pen`. Формат файла не меняется, параллельная работа над форматом (`pdf-annotate`) не задевается, индекс можно в любой момент пересобрать. Ключ свежести — `meta.modified`.
4. **Поиск — простая нормализация и вхождение всех слов** (нижний регистр, ё→е). На объёмах личных заметок это быстрее и предсказуемее полнотекстового движка.
5. **Обёртки над `Task` через `suspendCancellableCoroutine`** — без лишней зависимости `kotlinx-coroutines-play-services`.

## Risks / Trade-offs

- [Нужны Google Play Services; на китайской прошивке HyperOS их может не быть] → экран сообщает о недоступности, остальное приложение работает. Проверить на устройстве.
- [Качество распознавания беглого почерка] → поиск по всем словам; при плохих результатах — поиск по любому слову и нечёткое сравнение.
- [Время первой индексации больших тетрадей] → прогресс и инкрементальность; индексация идёт только на экране поиска.
