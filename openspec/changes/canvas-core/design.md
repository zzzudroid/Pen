## Context

Каркас и диагностика пера готовы (`stylus-diagnostics`), но фактических данных о Focus Pen ещё нет: change делается до прогона диагностики по решению пользователя. Мотивация — в `proposal.md`, требования — в `specs/canvas/spec.md`.

## Goals / Non-Goals

**Goals:**
- Ядро, которое без переделки станет основой заметок, PDF, доски и рисования.
- Задержка «перо → пиксель» на уровне системных приложений.

**Non-Goals:**
- Сохранение на диск, страницы, фон-подложки — этап «Заметки».
- Лассо, пиксельный ластик, слои, тайловый кэш для тысяч штрихов — следующие changes.

## Decisions

1. **androidx.ink 1.0.0 вместо своего рендера.** `InProgressStrokesView` рисует активный штрих во фронт-буфер (graphics-core) и сам строит геометрию кисти с давлением. Свой рендер на OpenGL — недели работы ради того же результата. Ink стабилен и совместим с нашими AGP 8.7.2 / Kotlin 2.0.21 / SDK 35.
2. **Мировые координаты + матрица вида.** Штрихи хранятся в координатах «мира»; `Viewport` (масштаб + сдвиг) даёт матрицу мир→экран. Ink получает обратную матрицу при `startStroke`, поэтому штрих, нарисованный при любом масштабе, сразу оказывается в мировых координатах. Математика вьюпорта — чистый Kotlin, покрыта JVM-тестами.
3. **Слои отрисовки:** снизу `View` с готовыми штрихами (`CanvasStrokeRenderer`, матрица вьюпорта), сверху `InProgressStrokesView`. После `onStrokesFinished` штрих переносится в модель, нижний слой перерисовывается, затем штрих удаляется из верхнего — так нет мигания при передаче.
4. **Маршрутизация указателей в одном месте** (`DrawingSurface.onTouchEvent`): перо → рисование/ластик; пальцы → жесты; палец рисует только в режиме «рисовать пальцем». Перо «активно», пока касается или пока с последнего hover-события прошло < 500 мс — в это время пальцы игнорируются. Это предположение о hover проверим отчётом диагностики.
5. **Временный ластик** — любой бит `BUTTON_STYLUS_PRIMARY | BUTTON_STYLUS_SECONDARY` в `buttonState` или `TOOL_TYPE_ERASER`. Какая кнопка у Focus Pen реальная — узнаем из отчёта; набор битов вынесен в одну константу.
6. **Ластик через геометрию Ink:** на каждом движении строим отрезок в мировых координатах между прошлой и текущей точкой и проверяем пересечение с `PartitionedMesh` каждого штриха (с допуском по радиусу ластика). Все штрихи, стёртые одним движением, — одна команда истории.
7. **История — стек команд** (`AddStroke`, `EraseStrokes`), обобщённый и не зависящий от Android; в будущем станет журналом операций для сохранения.
8. **Предсказание движения** — `MotionEventPredictor` из `androidx.input`, предсказанное событие передаётся в `addToStroke`. Для пера запрашивается `requestUnbufferedDispatch`.
9. **Состояние холста живёт в ViewModel**, поэтому переживает поворот экрана.

## Risks / Trade-offs

- [Hover у Focus Pen может не работать] → защита от ладони останется на «перо касается» + системный `FLAG_CANCELED`; окно 500 мс — одна константа.
- [Кнопка пера перехвачена HyperOS] → временный ластик не сработает; останется инструмент на панели. Отчёт диагностики покажет.
- [Полная перерисовка нижнего слоя на каждый кадр жеста] → для сотен штрихов достаточно; при тысячах нужен тайловый кэш (отдельный change).
- [Ink-API в 1.x может отличаться от alpha-документации] → сверяем сигнатуры по фактическим классам библиотеки при сборке.
